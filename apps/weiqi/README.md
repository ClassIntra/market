# 围棋（weiqi）

ClassIntra 市场应用：**9 / 13 / 19 路**围棋，支持**人机练习**（服务器安装 KataGo 时自动启用强力 AI，否则回退本地 AI）、**本地双人**、**房间联机**（观战 / 聊天 / 双方确认数子 / 跨班对局）、**SGF 打谱复盘**与**本机棋谱库**（无需导入/导出文件）、**整盘 AI 复盘评级**与**断线恢复**。

前端不经过 Vite 构建，是运行时注入的原生 ES5 脚本；规则核心、AI、后端共用同一套实现，联机判定与本地一致。

## 功能

### 对弈

- 9 / 13 / 19 路，星位与坐标（字母跳过 I）自动适配；入场选项标注「快棋 / 标准 / 正式」
- **切换棋盘规格会强制重建网格、坐标、星位与棋子贴图缓存**，不会出现选了 13/19 路却还显示 9 路网格的问题
- 中国数子法，普通局贴 7.5 目；让子局（2–9 子）白先、贴 0.5 目
- 单劫 + **位置超级劫**、禁止自杀；服务端与本地使用同一核心
- 停一手、认输、悔棋；双方连续停一手进入数子
- **落子二次确认**：触屏默认开启，第一下出现确认环，再点同一点才落子；桌面可在设置中开关（Esc 取消）
- **猜先**：入场设置旁一键随机执黑/执白
- **数子阶段**：点选死子（自动重算双方地域），双方确认后终局；意见不一致可「继续下棋」
- **终局结果卡**：显示结果，可一键「复制结果」「复盘」或「再来一局」（本地/人机）
- 落子/提子/停一手区分音效，可关闭；轮到自己时棋盘有一圈淡主色提示
- 落子/提子动画、最后一手标记、手数显示、悬停幽灵子、非法点红环
- 键盘：方向键选点、回车落子、P 停一手、U 悔棋、空格（复盘）播放/暂停、Esc 退出复盘/抽屉

### 人机练习

- **服务器 KataGo（可选，推荐）**：部署端在 `Resources/engines/katago` 放好引擎与模型后，人机模式自动检测并启用；三档棋力映射到不同搜索预算，应手与分析都走服务器引擎，19 路棋力与稳定性明显优于本地 AI。引擎缺失、繁忙或超时（30 秒）时只降级当前一手，并显示「KataGo（重试中）」，10 秒后自动重新检测，不会整局退回本地 AI。
- 三档棋力：入门 / 进阶 / 高手（本地 AI 与 KataGo 共用同一档位选择）
- **开局手册**：第一手走天元/星位，第二手占离对手最远的星位，不再一上来下在一路或乱飞
- **战术定手**：大提子（≥2 子）和救回被打吃的大块（≥3 子）直接落子，不再花时间搜索；候选与模拟层过滤自打吃
- **19 路提速**：随机模拟截断到 240 手，把预算换成约 3 倍搜索次数；高手档降低随机扰动
- AI 运行在 **Web Worker**（同步搜索 + 过程性进度回传），主线程不卡顿；Worker 不可用时自动降级为同文件的主线程分片搜索
- **稳定性兜底**：Worker 崩溃/超时（6 秒）会取消搜索并自动走一手合法着法，不会把对局卡在「电脑思考中」；AI 连续返回非法着法、引擎脚本加载失败也会同样兜底，可悔棋重试；KataGo 失败只影响当前一手并自动重试，思考时显示已用时间
- 可执黑/执白、可让子；对手停一手且己方领先时会跟着停一手结束（只在后盘生效，避免开局误停）
- **AI 分析**：本地 / 人机 / 打谱可查看 Top-3 候选、黑胜率与面积差（布局阶段只显示胜率），点击候选在棋盘标出；结果随局面变化自动作废。装了 KataGo 时显示「KataGo 判断」与服务端候选
- **整盘 AI 复盘**：打谱模式或本地/人机终局后点「AI 复盘」，逐手分析整盘棋，给每手标出**妙手 / 本手 / 俗手 / 失误 / 恶手**，并显示损失胜率与 AI 推荐点；胜率曲线可点击跳转，自动列出「最大失误 Top3」，棋盘用金色虚线圈标出当前这手的 AI 推荐点；进度可暂停，结果缓存在当前会话
- 「提示」已合并进 AI 分析：默认用高手档为当前局面找一手，棋盘上画圈提示
- 未装 KataGo 时本地 AI 只按中国数子法做内部评估，适合入门与随手一盘；19 路棋力弱于 9/13 路

### 本地双人

- 同屏轮流落子，与联机共用规则、数子与复盘流程
- 可让子；支持悔棋与提示

### 房间联机

- 4 位房间码，创建 / 加入 / 观战；房主可开新局、关闭房间
- 服务端权威：落子、停一手、认输、悔棋、数子标死与确认全部经服务端校验
- 实时推送（`context.data.realtime`）+ 无实时通道时每 2.5 秒轮询兜底
- 房间快捷聊天（玩家与观战者均可发言），随房间关闭/空置销毁
- 快捷聊天短语：好棋 / 加油 / 再来一盘 / 谢谢，点一下直接发送
- 状态版本（rev）保护：迟到的轮询响应不会覆盖新落子，也不会打断待确认落子
- 观战替补：玩家离开后，最早的观战者递补其颜色
- **跨班对局**：配置中继时，凭房间码跨服务器加入；房间状态由建房服务器权威持有，请求经中继转发（与五子棋/象棋同构）

### 打谱复盘

- 导入 SGF（文件选择或粘贴），逐手回看；方向键换手、点棋谱跳转
- **自动复盘**：按 0.85 秒/手自动播放，可暂停；移动端开始播放后自动收起抽屉
- **AI 复盘评级**：逐手对比「实战着法」与「AI 最佳着法/落子后局面」的黑胜率差：≤1.5% 为本手，2–6% 为俗手，6–15% 为失误，>15% 为恶手；实战是最佳着法且与第二候选差距 ≥8% 时标为妙手。每手显示评级、损失与 AI 推荐点
- 本地/人机对局终局后可直接点「进入复盘」，无需先导出 SGF
- **本机棋谱库**：设备不支持文件导入/导出时，对局结束后会自动保存在本机（最多 30 盘），入场页点开即可复盘或删除；也可在对局中手动「存入棋谱库」。仍保留「粘贴棋谱」作为导入方式，复制棋谱文本仍可用
- 复制棋谱文本（不依赖文件）；桌面或支持下载的环境仍可下载 SGF；房间对局也可导出
- SGF 支持：`FF[4]` 主线、`AB/AW` 摆子、`HA` 让子、`KM` 贴目、`PL` 先行、`RE` 结果、`C` 注释（导出）
- 变例取第一条主线；中段摆子会给出提示并跳过
- 会话恢复：本地/人机对局离开后保存在本机，入场页可「继续上次」

## 规则说明

| 项 | 实现 |
|---|---|
| 计分 | 中国数子法（棋子 + 单色围空）；白贴 7.5 目，让子局白贴 0.5 目 |
| 提子 | 四邻接分组、气为 0 整组提掉 |
| 自杀 | 禁止（提子后己方仍无气则非法） |
| 劫 | 单劫 + 位置超级劫（禁止重复出现过的全局局面） |
| 终局 | 双方连续停一手 → 数子；死子由双方点选，双方确认后结算 |
| 让子 | 2–9 子标准星位；白先 |
| 日韩数目 | 规则核心支持（SGF `RU[Japanese/Korean]` 导入时按数目法显示），界面建房只提供中国规则 |

> 数子阶段的死子需要人来判断；核心不替用户判断死活。空区同时接触黑白双方时按中立处理（简化处理，不单独识别复杂双活）。

## 服务器端 KataGo（可选）

市场包**不包含**引擎二进制与模型（`.exe` / `.dll` / `.bin.gz` 不在市场文件白名单内），由部署端放在服务器目录：

```
<服务器根>/Resources/engines/katago/
├── katago.exe          # OpenCL 版；katago-eigen.exe 为 CPU 后备
├── model.bin.gz        # b18c384nbt（约 98MB，OpenCL 下 9/19 路 60 visits 约 3.5 秒）
├── analysis.cfg        # analysis 模式配置（见下）
├── KataGoData/         # OpenCL 自动调优缓存（首次运行生成）
└── *.dll               # katago.exe 依赖的 OpenSSL / VC++ / zlib 等运行库
```

引擎目录查找顺序：环境变量 `WEIQI_KATAGO_DIR` → `<服务器根>/Resources/engines/katago` → `<仓库根>/Resources/engines/katago` → 应用内 `backend/engine`。

`analysis.cfg` 最小示例（按机器配置调整线程数）：

```
logDir = analysis_logs
reportAnalysisWinratesAs = BLACK
numAnalysisThreads = 1
numSearchThreads = 4
nnMaxBatchSize = 2
maxVisits = 1000
warnUnusedFields = false
```

模型：统一使用 `model.bin.gz`（当前为 **b18c384nbt**，约 98MB）。OpenCL 下实测 9 路 / 19 路 60 visits 都约 3.5 秒；`model-b10c128.bin.gz` 与 `model-fast.bin.gz`（b6c96）作为后备。纯 CPU 后备可换回 `katago-eigen.exe`，但大模型会慢很多。换模型只需替换 `model.bin.gz`。

运行方式与保护：

- 一台服务器只启动 **一个** `katago analysis` 子进程，请求**串行排队**（队列上限 3），避免打满 CPU；卸载应用时由 `backend/cleanup.js` 关闭进程
- 应手预算：入门 24 visits / 1.8 秒，进阶 56 / 3.3 秒，高手 120 / 7 秒；单项分析：32 / 56 / 100 visits；整盘复盘：每手 20 visits / 1.3 秒
- 单次查询 20 秒超时；进程崩溃或超时后进入 10 秒冷却并自动重启；仍失败时前端回退本地 AI（前端另有 30 秒兜底）
- 前后端通过 `/api/weiqi/ai/status`、`/ai/warmup`、`/ai/move`、`/ai/analyze`、`/ai/review` 交互，均需登录；AI 接口有 300ms/用户 的频率限制
- 接口返回 `engine: 'katago'`、黑视角胜率/目差、候选与 PV；前端据此显示「KataGo 判断」「AI 引擎：KataGo（服务器）」

验证：

```bash
# 状态（应返回 available: true）
curl -H "Cookie: <登录态>" http://<服务器>/api/weiqi/ai/status
# 预热（首次会加载模型，通常 1–3 秒）
curl -X POST -H "Cookie: <登录态>" http://<服务器>/api/weiqi/ai/warmup
```

## 兼容与性能

- 目标基线：Chrome 80 / 腾讯 X5 Chromium 89；全文件 `var` / `function` / 单引号，无箭头函数、模板字符串、`class`、可选链、`async/await`
- 不用 `flex/grid gap`、`aspect-ratio`、`:is/:where`、容器查询、`inset`、`backdrop-filter`
- 棋盘用 Canvas 2D：木纹背景与黑白棋子贴图按尺寸/DPR 缓存，一次落子只重绘棋盘层
- `ResizeObserver` + 窗口 resize + 900ms 低频兜底；回调延迟到下一帧改画布尺寸，避免观察器循环告警
- 触屏 `touch-action: none` + Pointer Events；桌面悬停幽灵子、移动端按压落子
- **不依赖 Service Worker**：市场静态资源由宿主缓存；AI 的 Web Worker 不可用时自动进入**主线程时间片兼容模式**（每片约 10ms，不冻结触屏界面），界面会显示「兼容模式」
- **KataGo 在服务器进程外运行**：OpenCL 版跑核显（Intel UHD 730 实测 b10c128 约 157 visits/s、b18c384nbt 约 18 visits/s @19 路），Eigen 版可作 CPU 后备；前端只发 HTTP 请求，不下载引擎/权重
- 触屏目标按平板加大：按钮 36px、棋谱行 38px、快捷语 32px；适配底部手势条安全区
- 深色主题跟随宿主 `data-theme`；`prefers-reduced-motion` 下关闭动画
- 卸载契约：所有订阅、计时器、Worker、音频上下文、宿主导航栏注入都在 `context.app.onDestroy` 中回收；`backend/cleanup.js` 删除自建表
- 不依赖文件选择/下载：棋谱自动存入宿主 `data.storage`（最多 30 盘），设备无法导入导出文件时仍可复盘；清空浏览器数据会一并清除本机棋谱

## 开发与验收

```bash
# 静态审查（ES5 / CSS 令牌 / 资源回收 / 危险 API）
node scripts/market-review.mjs market-apps/weiqi

# 装前预检（与安装时同一校验器）
node scripts/diag.js market weiqi

# KataGo 适配器自检（有引擎时 available=true；不会常驻进程）
node -e "var e=require('./market-apps/weiqi/backend/engine');console.log(e.status());e.shutdown()"

# 同步到市场仓（主仓 market-apps/ 被 gitignore，实际发布走 market 仓）
.\scripts\sync-market.ps1 -App weiqi
node scripts/market-index-gen.mjs
```

本地修改后请重新走一遍 `market-review` 与 `diag`；联机接口建议用测试账号验证「建房 → 双人落子 → 双停数子 → 双方确认 → 开新局」全链路。

- **界面与美术** `frontend/entry.js`、`frontend/style.css`、`icon.svg`：Canvas 木纹与棋子、响应式布局、深色主题、动效与键盘/触屏交互；全部自绘，未使用第三方图片或字体文件
- **联机后端** `backend/routes.js`：房间生命周期、服务端走子校验、双方确认数子、聊天、跨班目录与中继转发

## 已知限制

- 未安装服务器 KataGo 时，AI 为轻量 MCTS，不使用神经网络；19 路棋力有限，9/13 路体验更好。装了 KataGo 后 19 路由服务器引擎负责，棋力取决于部署机器的 CPU 与权重
- 服务器端 KataGo 由部署方自行安装与维护；市场包不含二进制与权重，卸载应用会关闭引擎进程但不删除引擎目录
- AI 分析的面积差来自静态数子，布局阶段参考意义有限（界面在布局阶段只显示胜率）
- 无读秒/包干等计时器；无分支变化树（SGF 变例只取第一条主线）
- 日韩数目法只在导入 SGF 时用于显示，建房只提供中国规则；双活等复杂死活由人工在数子阶段标定
- 跨班对局依赖部署端中继配置；无实时通道时依赖轮询（约 2.5 秒状态、10 秒聊天）
- 本机棋谱库最多保存 30 盘，依赖宿主 `data.storage`；清除浏览器/应用数据会丢失，且不做云端同步
- 房间与聊天在关闭/空置后清理；闭房 24 小时后随建房时的清理任务删除
